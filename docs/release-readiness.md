# 节点发布前检查

本文件只记录服务端的发布要求。启动器打包、Qt 运行时、Windows 签名及外部电脑启动问题应在启动器仓库维护，不作为节点已验收的依据。

## 自动测试

从节点仓库根目录运行标准 unittest：

```sh
python -X utf8 -m unittest discover -s tests -p "test_*.py" -v
```

安装启动器测试依赖并准备相邻源码后，在启动器仓库运行对应 unittest 用例。逐项覆盖和 P2P 命令见 [测试说明](../tests/README.md)。CI 运行本仓库用例，未包含跨公网网络环境、真实 Minecraft 世界或真实 SMTP 收件。

不要将历史测试总数当作当前代码的结果。发布记录应保存提交号、Python/操作系统版本、执行命令、用例结果和未执行项；日志中不得包含接入码或用户秘密。

发行包在 Windows 与 Linux 分别原生构建，使用 [发行包验收](packaging.md) 测试真实可执行文件。Windows 干净机器、签名和 SmartScreen 状态不能用 CI 或源代码单测替代。

## 需要实际验收的环境

- 两台处于不同网络的客户端验证 P2P，记录候选类型和实际路径；覆盖家庭 NAT、双重/对称 NAT、IPv6、UDP 阻断和中继回退。本机直连不能代替公网打洞验证。
- 同房间混合 P2P 与中继，多访客并发、传输完整性、EOF 与断线清理；关闭归属节点后验证重建及访客重连。
- 真实 Minecraft 首次进服、区块加载、视距和模组负载，校准单人预算与预留带宽。默认预算不是峰值实测或流畅保证。
- 真实 SMTP 收件、邮件显示、验证码绑定/过期/重放/限速，以及服务不可用时的错误提示。
- 首次浏览器向导、可信 HTTPS、服务账户权限、备份恢复、升级回滚与端口/防火墙规则。参考 [部署说明](deployment.md)。

## 凭据与数据

密钥、联邦邀请、管理员密码、SMTP 授权码、账号副本、好友事件和本地/远程测试配置不得提交仓库或打入发行包。已经公开的服务器密码、管理员密码、个人码或邮箱授权码必须轮换，删除文件不能撤销泄露。

用户名路由、账号 ID、公钥和好友签名事件会在联邦传播；身份包才是用户授权的加密副本。登录节点可能接触密文，弱密码仍可能被离线猜测；恶意节点网页也可能窃取输入，不能声称运营者完全不可信时仍可安全输入密码。

个人接入码最长七天，网页登录退出不会即时撤销已经签发的码。更改普通接入码领取密码也不会撤销旧码。SMTP 授权码明文存于节点 `smtp.json`，操作系统权限和备份权限属于保护边界。

## 能力边界

联邦不聚合带宽，也不自动抵御容量型 DDoS。没有外部防护入口和源站访问限制，不能隐藏源站地址。归属节点失效会断开现有 TCP 和游戏会话；重建与重连不能表述为无缝迁移。

节点本地隔离不是全网封禁；共享入网密钥泄露后可能换身份重入。用户名预约只覆盖可联系的已知成员，网络分区合并可能产生重名，应允许使用完整账号 ID。

向公众提供中转服务可能需要电信业务许可；部署者应自行确认适用要求并承担合规责任，见 [README 提示](../README.md#部署者责任提示)。

依赖版本固定和测试通过不等于独立安全审计，也不表示上述真实环境全部通过。
